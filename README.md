# LangGraph RAG + SQL Agent

Веб-приложение на основе **LangGraph** и **FastAPI** для работы с документами (RAG) и данными в ClickHouse (Text‑to‑SQL).  
Агент разделён на два независимых режима, что исключает путаницу и гарантирует точные ответы.

---

## 🔥 Возможности

- **Два режима работы**:
  - 📄 **RAG (поиск по документам)** – загружайте PDF, TXT, DOCX и задавайте вопросы по их содержанию.
  - 🗄️ **SQL (запросы к базе)** – задавайте вопросы на естественном языке, и система сгенерирует и выполнит SQL-запрос к ClickHouse.
- **Локальная работа без интернета** – используется Ollama (LLM) и векторная база Chroma.
- **Простой и понятный веб‑интерфейс** на русском языке.
- **Готов к запуску в Docker** – все сервисы поднимаются одной командой.

---

## 🧩 Стек технологий

- **Backend**: FastAPI, LangChain, LangGraph, ClickHouse‑connect
- **LLM**: Ollama (локально) с моделями `llama3.2:3b` и `nomic-embed-text`
- **База данных**: ClickHouse (в Docker)
- **Векторное хранилище**: Chroma (локально, в томе Docker)
- **Фронтенд**: HTML, CSS, JavaScript (без внешних зависимостей)

## 🚀 Запуск (локальная разработка)

### 1. Клонируйте репозиторий
	
```bash
git clone https://github.com/ваш-username/langgraph-rag-sql-agent.git
cd langgraph-rag-sql-agent
```
  
### 2. Настройте переменные окружения (опционально)
Создайте файл `.env` (можно скопировать из `.env.example`). По умолчанию используются значения, указанные в `docker-compose.yml`.

### 3. Запустите сервисы
	
```bash
docker-compose up -d
```

Эта команда поднимет:

- **ClickHouse** (порты `8123`, `9000`)
- **Приложение** (порт `8000`)

> **Примечание:** Приложение использует `network_mode: host` для доступа к Ollama на хосте. Убедитесь, что Ollama запущен и слушает на `0.0.0.0:11434` (см. раздел «[Настройка Ollama](#настройка-ollama-для-доступа-из-контейнера)»).

### 4. Откройте браузер

Перейдите по адресу: [http://localhost:8000](http://localhost:8000)

## 🛠️ Настройка Ollama для доступа из контейнера

По умолчанию Ollama слушает только на `127.0.0.1`. Чтобы контейнер мог к нему обращаться, запустите его с привязкой ко всем интерфейсам:

```bash
# Остановите текущий процесс
pkill ollama

# Запустите с привязкой к 0.0.0.0
OLLAMA_HOST=0.0.0.0 ollama serve &
```

Проверьте, что теперь порт 11434 слушает на `0.0.0.0`:

```bash
ss -tulpn | grep 11434
```

Должно быть: `0.0.0.0:11434` (или `*:11434`).

## 🗄️ Инициализация базы данных (ClickHouse)
Скрипт инициализации создаёт тестовую таблицу sales с примерами данных. Выполните его один раз (после запуска ClickHouse):

```bash
# Если скрипт лежит на хосте
python init_db.py

# Или внутри контейнера
docker exec -it langgraph-agent python /app/init_db.py
```
Вы можете расширить `init_db.py`, добавив свои таблицы.

## 🔍 Режимы работы

### 📄 RAG (поиск по документам)
- На главной странице нажмите **«Поиск по документам»**.
- Загрузите файл (поддерживаются `.txt`, `.pdf`, `.docx`).
- Задайте вопрос – система найдёт ответ в загруженных документах.

### 🗄️ SQL (запросы к базе)
- На главной странице нажмите **«Запрос к базе данных»**.
- Задайте вопрос на естественном языке (например, *«покажи первые три строки из sales»*).
- Система сгенерирует SQL-запрос, выполнит его в ClickHouse и вернёт результат.

---

## 💬 Примеры запросов

| Режим | Вопрос | Ответ |
|-------|--------|-------|
| SQL | «Какие таблицы есть в базе?» | `sales` (и другие, если созданы) |
| SQL | «Покажи все данные из sales» | Таблица с полями `id`, `product`, `amount`, `sale_date` |
| SQL | «Сколько записей в sales?» | Число (например, 5) |
| RAG | «Что такое chain‑of‑thought?» | Извлечённый текст из загруженного документа |
| RAG | «Сколько надо заплатить?» | Сумма из квитанции (если загружен соответствующий PDF) |

## ⚙️ Переменные окружения

Настройки задаются через переменные окружения (см. `app/config.py`). Основные:

| Переменная | Описание | По умолчанию |
|------------|----------|--------------|
| `LLM_MODEL` | Модель для ответов | `llama3.2:3b` |
| `EMBEDDINGS_MODEL` | Модель для эмбеддингов | `nomic-embed-text` |
| `OLLAMA_HOST` | Хост Ollama | `localhost` |
| `OLLAMA_PORT` | Порт Ollama | `11434` |
| `CLICKHOUSE_HOST` | Хост ClickHouse | `localhost` |
| `CLICKHOUSE_PORT` | HTTP‑порт ClickHouse | `8123` |
| `CLICKHOUSE_USER` | Пользователь ClickHouse | `default` |
| `CLICKHOUSE_PASSWORD` | Пароль ClickHouse | (пусто) |
| `CLICKHOUSE_DATABASE` | База данных | `default` |
| `CHROMA_PERSIST_DIR` | Папка для Chroma | `./chroma_db` |

## 🔧 Устранение неполадок

### Ошибка подключения к Ollama
- Убедитесь, что Ollama запущен и слушает на `0.0.0.0:11434`.
- Проверьте доступность из контейнера:  
  `docker exec langgraph-agent curl -s http://172.17.0.1:11434/api/tags`

### Ошибка Recursion limit в RAG
- Увеличьте `recursion_limit` в вызове `rag_agent.invoke()` (например, до 50).

### Нет таблиц в ClickHouse
- Запустите скрипт инициализации: `python init_db.py` (или через Docker).

### Не сохраняются загруженные документы
- Проверьте права на папку `uploads/` (она создаётся автоматически).
